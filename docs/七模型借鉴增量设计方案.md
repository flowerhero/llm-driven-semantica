# 七模型借鉴增量设计方案（smini-extract v7 候选）

> 状态：**A/B 组已确认实施** · C 组（queries 通道）待用户拍板
> 日期：2026-09-06
> 依据：对 `ontology-driven-dev-main/` 七模型（M1/M2/M3/M5/M6/M7/MU）的借鉴分析，
> 保持我方 smini-extract 的**能力范围与实现机制**不变（契约即规则 · 宿主 LLM 抽取 ·
> 薄壳映射 + 惰性锚点 · 零抽取规则 · evidence 溯源 · JSON + HTML 查看器产出）。

---

## 一、借鉴原则

> **借字段语义，不借执行机制。**

对方七模型的价值不在其生成引擎（DDL / simpleeval / flow_engine / UI 生成——
与"读端"定位冲突），而在其揭示的建模维度。我方按"字段级增强 → 结构级增强 →
新通道（需确认）"三个层次借鉴，全部新增内容继续遵循：
LLM 语义判断 → 薄壳枚举校验 + 非法兜底 → evidence 溯源 → validate 可验证。

## 二、A 组：字段级增强（6 项，机制零影响）

| # | 借鉴来源 | 落点通道 | 新增字段 | 枚举/兜底 |
|---|---|---|---|---|
| A1 | M3 规则模型 | `rules` | `rule_type`：规则用途（校验/推导/触发），与 modality（道义模态）**正交并存** | `RuleType`：VALIDATION / DERIVATION / TRIGGER / OTHER；非法→OTHER |
| A2 | M3 规则模型 | `rules` | `output_type`：规则输出取值形态（复用函数指标枚举） | 复用 `FunctionOutputType`；非法→OTHER |
| A3 | M3 规则模型 | `rules` | `reused_by`：该规则被哪些流程/函数引用（引用名数组） | list[str]，薄壳清洗；找不到引用仅软警告 |
| A4 | 对方 A/B 内容分级 | `rules`/`attributes` | `certainty`：行业通用 / 企业专属（企业参数如"≤3000元""14天"打标，供未来人工复核） | `Certainty`：GENERAL / ENTERPRISE / OTHER；非法→OTHER |
| A5 | M6 流程模型 | `processes` | `preconditions` / `postconditions`：流程级前后置条件 | list[str]，可空 |
| A6 | M6 流程模型 | `processes.steps` | `kind` 枚举扩展：START / END / SYSTEM_TASK（保留 TASK/GATEWAY/EVENT） | `StepKind` 扩展；非法→TASK |
| A7 | M5 主体模型 | `permissions` | `role`：角色中间层（权限经角色授予）· `actor_type`：HUMAN / SYSTEM | `ActorType`：HUMAN/SYSTEM/OTHER；非法→OTHER |
| A8 | M2 行为模型 | `actions` | `precondition` / `postcondition`：动作执行前后置 | str，可空 |
| A9 | M1 对象模型 | `attributes` | `required`：属性必录性 · `value_type` 扩展 `DICT_REF`（字典引用）/ `ENTITY_REF`（实体引用） | bool 默认 False；`AttributeValueType` 扩展；非法→OTHER |

## 三、B 组：结构级增强（3 项）

| # | 借鉴来源 | 落点 | 内容 | 机制影响 |
|---|---|---|---|---|
| B1 | M6 SUB_FLOW_CALL | `processes.steps` | `sub_process_ref`：步骤可引用另一流程（子流程嵌套） | 薄壳仅校验引用存在性（软警告），不展开执行 |
| B2 | manifest / 模型头 | 输出顶层 | `document_meta`：{domain, source, version, doc_type} 文档元数据头 | 薄壳从输入文档派生 source/version，domain 可选 |
| B3 | 对方一致性门禁 | `validate` | **软引用检查**（warning 不阻断）：reused_by / sub_process_ref / permissions.actor / actions.actor 可解析性 | validate 输出 warnings 区 |

## 五、契约变更汇总（宿主交卷新增字段）

```
entities:    [{ surface, canonical, type }]                          （不变）
relations:   [{ subject, predicate, object, object_type, evidence, prop_kind?, strength? }]（不变）
attributes:  [{ entity, name, value, value_type, evidence, required? }]  ← required 新增
rules:       [{ subject, condition, action, modality, evidence,
                rule_type?, output_type?, reused_by?, certainty? }]     ← 4 项新增
processes:   [{ name, description, steps, flows,
                preconditions?, postconditions? }]                      ← 2 项新增
  steps:     [{ label, kind, actor, evidence, sub_process_ref? }]       ← sub_process_ref + kind 扩展
actions:     [{ name, actor?, level, target?, side_effect?, trigger?, evidence,
                precondition?, postcondition? }]                        ← 2 项新增
permissions: [{ actor, action, effect, scope?, evidence, role?, actor_type? }] ← 2 项新增
+ 输出顶层 document_meta
```

## 六、兜底与验证规则

| 项目 | 规则 |
|---|---|
| 枚举兜底 | rule_type→OTHER · certainty→OTHER · actor_type→OTHER · value_type 新值合法 · kind 新值合法 |
| 可空性 | reused_by/preconditions/postconditions/sub_process_ref/role/precondition/postcondition 均可空 |
| ID 锚点 | 内容寻址键**不变**（rule_id 仍由 subject+condition+action+modality 计算），新增字段不参与寻址 |
